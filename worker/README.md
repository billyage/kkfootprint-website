# REX booking-lead Worker

This Worker receives booking leads and live website-chat messages, validates and normalizes the browser payloads, and forwards signed JSON payloads to n8n. The n8n webhook URLs and shared signing secret exist only in Worker secrets.

## Required configuration

Set these Worker secrets (do not store them in Git):

```text
N8N_WEBHOOK_URL=https://your-private-n8n-tunnel-host/webhook/your-booking-intake-path
N8N_CHAT_WEBHOOK_URL=https://your-private-n8n-tunnel-host/webhook/your-rex-chat-path
REX_CUSTOMER_HMAC_SECRET=<long-random-shared-secret>
```

Set these Worker variables:

```text
ALLOWED_ORIGINS=https://kkfootprint-website.billyage89.workers.dev
MAX_PAYLOAD_BYTES=16384
TURNSTILE_ENABLED=false
```

`ALLOWED_ORIGINS` must contain exact origins (scheme and host; optional port). Do not use wildcards. `MAX_PAYLOAD_BYTES` defaults to 16 KB and cannot exceed 64 KB.

When Turnstile is introduced, set `TURNSTILE_ENABLED=true` and store `TURNSTILE_SECRET_KEY` as a Worker secret. The landing page must then send its Turnstile token in `turnstileToken`. The Worker verifies both the token and that Turnstile reports the same hostname as the request origin.

## Browser request contract

The booking endpoint accepts only a JSON object with these keys:

```text
name, contact, email, tour, date, hotel, adults, children,
type, vehicle, requests, turnstileToken
```

`name`, `contact`, `tour`, `adults`, and `children` are required. Any other field is rejected. `turnstileToken` is consumed by the Worker and is never forwarded to n8n. n8n receives the fixed source value `website_booking_form`.

## n8n payload and HMAC verification

The Worker forwards this exact JSON shape to `N8N_WEBHOOK_URL`:

```json
{
  "requestId": "UUID generated by the Worker",
  "receivedAt": "2026-09-01T00:00:00.000Z",
  "source": "website_booking_form",
  "booking": {
    "name": "...",
    "contact": "...",
    "email": "...",
    "tour": "...",
    "date": "...",
    "hotel": "...",
    "adults": 2,
    "children": 0,
    "type": "...",
    "vehicle": "...",
    "requests": "..."
  }
}
```

It sets these headers:

```text
Content-Type: application/json
X-REX-Request-Id: <requestId>
X-REX-Timestamp: <receivedAt>
X-REX-Signature: <lowercase hex HMAC-SHA-256>
```

The signature input is the UTF-8 byte sequence below, with no newline:

```text
<X-REX-Timestamp>.<exact raw JSON request body>
```

`X-REX-Signature` is the lowercase hexadecimal HMAC-SHA-256 of that input, keyed by `REX_CUSTOMER_HMAC_SECRET`. n8n must verify the signature against the raw request body before parsing or processing it, and reject timestamps older than a short window (for example, five minutes). It should also deduplicate `requestId`.

## Cloudflare setup

1. Deploy this Worker only after adding a route on the landing-page domain for `/api/rex/*`.
2. Store `N8N_WEBHOOK_URL`, `N8N_CHAT_WEBHOOK_URL`, and `REX_CUSTOMER_HMAC_SECRET` as Worker secrets, not variables.
3. Point `N8N_WEBHOOK_URL` at a dedicated Cloudflare Tunnel hostname and n8n intake webhook. Never expose the URL in browser code.
4. In n8n, validate the HMAC and timestamp, then route the validated lead to REX.
5. Recommended later: protect the tunnel hostname with Cloudflare Access service tokens, add Turnstile, and add Cloudflare WAF/rate-limit rules for `/api/rex/leads`.

The Worker does not yet implement Cloudflare Access service-token headers or rate limiting.

## Website chat contracts

`POST /api/rex/chat/start` accepts `name`, `telegram`, `email`, `language`,
`channel` (`customer_web`), `marketingConsent`, `privacyNoticeVersion`, and optional `turnstileToken`. n8n should
store the consent state and return JSON with an optional `conversationId` and `reply`.
If no conversation ID is returned, the Worker request ID is used.

`POST /api/rex/chat/messages` accepts `conversationId`, `message`, `language`, `channel` (`customer_web`), and
optional `turnstileToken`. n8n/REX must return JSON containing a non-empty `reply`.
Both endpoints use the same HMAC headers as booking leads. They use
`N8N_CHAT_WEBHOOK_URL` when configured and otherwise fall back to
`N8N_WEBHOOK_URL`.

All customer-webhook payloads forwarded to n8n include top-level `language` (`en`,
`zh`, or `ko`) and `channel: customer_web`. n8n must treat this channel as an
untrusted public customer conversation and apply the public tour-sales policy before
passing it to REX.
